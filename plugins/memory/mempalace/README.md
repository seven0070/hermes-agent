# MemPalace recall (opt-in, read-only)

This Hermes MemoryProvider reads an **existing, explicitly named** local palace. It does not ingest chats, mirror memory writes, or expose MemPalace write tools. MemPalace itself can still create or migrate local index/cache files when a search runs, so "read-only" here means no Hermes content is filed, not that the filesystem is guaranteed unchanged. Hermes' built-in memory stays the only automatic writer. There is no double writing. It cannot recall anything until you populate a MemPalace palace separately.

Install `mempalace` into the Hermes Python venv, initialize a palace with MemPalace's CLI, and set `MEMPALACE_PALACE_PATH=<absolute path to that palace>` in the active Hermes `.env`. Then choose `mempalace` as the external provider with `hermes memory setup` (or set `memory.provider: mempalace` in config.yaml), restart and verify `hermes memory status`. Only one external provider can be active. To stop it, unset `memory.provider`; built-in memory is unaffected. Back up the palace separately if it contains data you care about; Hermes' backup covers only HERMES_HOME unless you store the palace there.

The upstream MemPalace Hermes *writer* integration is still under review at https://github.com/MemPalace/mempalace/pull/1942. This is intentionally a smaller, read-only adapter, not that installer.
